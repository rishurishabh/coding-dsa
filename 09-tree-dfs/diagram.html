Tree DFS: which way does state flow?

Two shapes hide under one name. Top-down hands state to children as arguments; bottom-up builds state from what children return. Getting this backwards is the most common way this pattern goes wrong. Code lives in 09-tree-dfs/*.js.

top-down / state passed down
bottom-up / state returned up
result / side-channel answer

03-all-paths-with-backtrack.js

Top-down + explicit backtrack

One shared array, mutated and un-mutated — cheaper than a fresh array per call, but only if every push has a matching pop.

04-validate-bst-range.js

Top-down, shrink a constraint

3 looks fine next to its parent 4, but the range inherited from grandparent 5 already ruled it out.

05-diameter-of-tree.js

Bottom-up + side channel

Height is what the parent needs back. Diameter-through-this-node is a fact only this node can compute.

06-max-path-sum.js

Bottom-up + side channel + clamping

A branch that only subtracts gets clamped to 0 — opting out of it beats including it, on both the return and the side channel.

07-lowest-common-ancestor.js

Bottom-up search

Neither subtree alone can report the answer — only the node where both searches converge knows.

Merge Intervals: sort first, then one sweep

Every variant here starts with an ordering decision — sort by start or by end — that turns an all-pairs comparison into a single left-to-right pass. Code lives in 04-merge-intervals/*.js.

The core move

Sort by start, sweep, merge

Six variants

Same sort-and-sweep shape, different questions

01-merge-overlapping.js

Sort by start, sweep-merge

start ≤ prev.end means overlap. Extend prev.end to the max, don't just replace it.

02-insert-interval.js

Three-phase scan, no re-sort

No sort needed — the list was already clean. Just split into before / overlapping / after in one pass.

03-interval-intersection.js

Two-pointer across two lists

Advance whichever interval ends first — it can't overlap anything further ahead in the other list.

04-max-overlap-sweep.js

Separate start/end sweep

Sort starts and ends separately; sweep both. The running total's peak is the answer — no need to track which intervals overlap.

05-greedy-non-overlapping.js

Sort by END, greedy keep/drop

Sorted by end, keeping the soonest-finishing interval always leaves the most room for what comes next.

06-free-time-gaps.js

Merge, then read the complement

Merge every schedule into the true busy periods first — whatever falls strictly between two of them is free by definition.

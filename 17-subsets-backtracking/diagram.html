Backtracking: choose, explore, un-choose

Every branch of the decision tree pushes a choice, recurses into everything that follows from it, then pops the choice back off before trying the next one. Code lives in 17-subsets-backtracking/*.js.

Seven variants

01-subsets-include-exclude.js

Choose forward from `start`

Every partial path IS a valid subset — recorded on entry, extended only forward.

02-subsets-with-duplicates.js

Variant 1 + same-level duplicate skip

Sorting groups duplicates adjacent — a simple `nums[i] === nums[i-1]` check prunes the redundant branch.

03-permutations.js

Loop restarts from 0, tracked by `used`

Order matters, so every index is a candidate at every position — except whatever's already chosen.

04-combination-sum.js

Recurse with `i`, not `i+1`

One index-vs-index+1 change is the entire difference from "each used once" to "unlimited reuse".

05-palindrome-partitioning.js

The choice is WHERE to cut

The search space is cut positions, not elements — a piece only gets explored if it's legal first.

06-n-queens.js

Constraint satisfaction

Three Sets (column, and both diagonal directions) turn "is this square attacked" into an O(1) check.

07-word-search.js

Backtracking on a grid

No separate visited grid — the board's own cell temporarily holds the marker, then gets its letter back.

Top K: push, then evict the worst

A heap capped at size K. Every new arrival gets pushed in; if that tips the heap past K, whatever's worst gets popped right back out. Code lives in 14-top-k-elements/*.js.

Five variants

One eviction shape, five definitions of "worst"

01-kth-largest-heap.js

Fixed-size min-heap

Once the heap holds K elements, its minimum IS the Kth largest — no sorting required.

02-top-k-frequent.js

Same heap, keyed by a derived count

Count first with a plain Map, then run the exact same eviction loop keyed on the count instead of the value.

03-k-closest-points.js

Same heap, direction flipped to max

"Worst" is now the largest distance — swap the comparator, keep the rest of the algorithm identical.

04-kth-largest-stream.js

Persistent heap across calls

The heap is a class field, not a local variable — it remembers everything between calls.

05-top-k-frequent-words.js

Same heap, two-part comparator

Same frequency isn't a tie for the heap — the second comparator rule decides who's "worse" and goes first.

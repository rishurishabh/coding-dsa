K-way merge: one candidate per source, always

The heap never holds more than K elements — one frontier value from each source. Pop the smallest, and that source's next value takes its place. Code lives in 15-k-way-merge/*.js.

Five variants

One heap discipline, five kinds of "source"

01-merge-k-lists.js

One heap slot per source, linked lists

Each list's current head competes; the winner extends the merged output and its own list's next node re-enters.

02-merge-k-sorted-arrays.js

Same mechanism, tracked by indices

Same one-slot-per-source rule — "where this came from" is an index pair instead of a pointer.

03-kth-smallest-in-matrix.js

Variant 2's merge, stopped early

The kth pop IS the answer — merging the rest of the matrix would be wasted work.

04-smallest-range-k-lists.js

Variant 2's merge, read as a window

Every pop redefines the range's edges — the merge stops the instant any list runs dry.

05-k-pairs-smallest-sums.js

A virtual merge over generated sources

Fixing i and sweeping j through nums2 IS a sorted sequence — the heap merges it without it ever being materialized.

LCS family: one grid, read six ways

Every cell in the grid is built from at most three already-finished neighbors: diagonal, directly above, and directly left. Code lives in 21-lcs-family/*.js.

match — diagonal + 1
mismatch — from above or left
target cell

The core move

dp[i][j] = match ? diagonal + 1 : max(above, left)

Six variants

One grid, read as a subsequence, a substring, or an edit cost

01-longest-common-subsequence.js

Carry forward on mismatch

Mismatch never loses progress — the better neighbor's count carries through unchanged.

02-longest-common-substring.js

Reset to 0 on mismatch

A broken run can't be patched — dp[i][j] means "run ending here", not "best answer so far".

03-edit-distance.js

Three moves instead of two

Match still costs nothing — a mismatch now picks the cheapest of three edits, not two lookups.

04-longest-increasing-subsequence-dp.js

Collapse to 1D, O(n²)

One sequence compared against itself index-by-index — same "anchored" framing as variant 2.

05-longest-increasing-subsequence-binary-search.js

Greedy + binary search, O(n log n)

Not DP — a different technique answering the same question faster, when only length matters.

06-shortest-common-supersequence-length.js

Reduce to variant 1 via counting

Shared characters get typed once, not twice — the LCS count is all that needs subtracting.

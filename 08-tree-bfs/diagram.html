Tree BFS: know where a level ends

A queue alone gives breadth-first order. Snapshotting its size before draining a level is what turns that into "process exactly this depth, then stop." Code lives in 08-tree-bfs/*.js.

The core move

Snapshot the queue's size, then drain exactly that many

Six variants

One snapshot trick, six different jobs

01-level-order-traversal.js

Queue + level-size snapshot

Each level's drain loop produces exactly one array. This is the foundation every other variant builds on.

02-level-order-sentinel.js

Queue + sentinel marker

No size math — popping the marker itself IS the level boundary.

03-zigzag-level-order.js

Snapshot + direction toggle

The queue order never changes — only whether the finished level array gets reversed before saving.

04-right-side-view.js

Snapshot, keep one node

The last node popped in each level's loop is provably the rightmost — no need to keep the rest.

05-minimum-depth.js

Snapshot + early exit

9 is a leaf found at depth 2. BFS returns immediately — 15 and 7 are never even dequeued.

06-connect-level-pointers.js

Snapshot, mutate not collect

prev.next = node falls straight out of the drain loop's pop order — no output array needed at all.

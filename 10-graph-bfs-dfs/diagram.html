Graph BFS/DFS: the one thing trees didn't need

A tree never revisits a node, so tree traversal never needed a visited set. A graph can have cycles — without tracking what's been seen, DFS or BFS on one loops forever. Code lives in 10-graph-bfs-dfs/*.js.

Eight variants

One visited-set discipline, eight different uses

01-grid-flood-fill.js

DFS flood fill

Each cell is a node; up/down/left/right are its edges. Marking a cell visited the moment it's entered stops double-counting.

02-connected-components.js

DFS + visited set, adjacency list

Same flood-fill idea as variant 1, with edges looked up in an adjacency list instead of read off coordinates.

03-multi-source-bfs.js

BFS seeded with ALL sources

Every source starts in the queue at distance 0 — one BFS run covers all of them at once.

04-shortest-path-bfs.js

Single-source BFS, track distance

BFS visits nodes in increasing distance order — no need to compare paths, the first arrival IS the shortest.

05-clone-graph.js

DFS + visited map storing CLONES

The visited map's value is the clone itself — revisiting a node via a cycle just reuses it instead of recursing again.

06-cycle-detection-undirected.js

DFS + remembered parent

Every undirected edge is stored both ways, so the node you just came from always looks "visited" — parent tracking excludes it.

07-cycle-detection-directed.js

DFS + three states, not two

A finished node can be reached again safely — only a node still on the current call stack signals a real back-edge.

08-bipartite-check.js

BFS + 2-coloring

Every neighbor must flip color. A same-colored edge, discovered the moment it's seen, proves no split exists.

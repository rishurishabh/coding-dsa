Sorting: compare-and-swap, or just count

Six algorithms here only ever ask "is A bigger than B?" — that question alone caps them at O(n log n). The seventh sidesteps the question entirely. Code lives in 00-sorting-algorithms/*.js.

Six comparison shapes, one non-comparison exception

01-bubble-sort.js

Repeated adjacent swaps

Every full pass without a swap means the array is already sorted — that's the early exit.

02-selection-sort.js

Repeated find-min-and-place

Exactly one swap per position, no matter the input — n-1 swaps total, always.

03-insertion-sort.js

Grow a sorted prefix

Cost is proportional to how unsorted the input is — O(n) if it's already sorted.

04-merge-sort.js

Divide, merge on the way back up

Two sorted halves merge in one linear pass — same two-pointer idea as merging intervals.

05-quick-sort.js

Divide via partition, not midpoint

The same partition step as quickselect — sorting both sides instead of discarding one.

06-heap-sort.js

Heapify, then repeated extract-max

The array IS the heap — no separate structure, unlike the Heap class used elsewhere in this repo.

07-counting-sort.js

Count values, never compare them

Sidesteps the O(n log n) comparison floor entirely — but only works when the value range is small.

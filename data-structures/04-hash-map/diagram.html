Hash map: a key, hashed into an index

A hash function turns any key into an array index — collisions (two keys, one slot) are the entire reason variants 1 and 2 differ. Code lives in data-structures/04-hash-map/*.js.

Five files

Two ways to resolve collisions, three problems that need O(1) lookup

01-hash-map-chaining.js

Buckets of key/value pairs

Simple, degrades gracefully — a collision only costs a short scan within one bucket.

02-hash-map-open-addressing.js

Linear probing, flat array

Better cache locality — one contiguous array, no per-slot list allocation.

03-two-sum.js

O(1) "seen the complement" lookup

One pass builds AND queries the same map — O(n), not the brute-force O(n²) pair check.

04-group-anagrams.js

Keying by a canonical value

Sorting each word makes every anagram of it produce the exact same map key.

05-longest-consecutive-sequence.js

Set membership as existence check

Only true sequence starts walk forward — every number still visited only once total.
